The browser runner now generates a temporary localhost SAN certificate and verifies trust during startup. Existing browser flows retain their previously scoped test-only browser certificate handling; the new `--tls-only` path uses HTTPX/SSL with validation enabled and does not invoke a browser. No certificates or keys are committed. Networked Ubuntu probes establish neither Windows behavior nor clinical readiness. No reverse proxy is introduced; direct TLS and `--no-proxy-headers` are the design. A future proxy requires a new explicit trust boundary.

Read refetch is permitted; writes fail offline and are not automatically retried/queued. Unknown outcomes still require server reconciliation and, for billing, reuse of the original idempotency key with the same payload. This task does not add durable client queues or solve cross-reload user resubmission ambiguity.
