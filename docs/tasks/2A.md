# Sprint 2 Task 2A — Administrative patients

Backend only. Next task: **2B**. Existing unfinished frontend and AGENTS.md edits were preserved and excluded from this checkpoint.

`0003_patients` creates stable UUID patient records and a patient action audit. Administrative fields are full name, phone as text, optional birth date, active status and timezone-aware creation/update/archive timestamps. No clinical fields are present in the table or API projection. The API exposes `POST /api/patients`, `GET /api/patients` (active records only; `page`, `page_size`, `search`), `GET /api/patients/{id}`, `PATCH /api/patients/{id}` and `POST /api/patients/{id}/archive`. Doctor and receptionist both use server-side `require_role` and CSRF protection. Archived records remain readable by ID but cannot be edited or archived again; they are never deleted.

A matching active name and phone produces HTTP 400 as a possible duplicate. Names alone are not unique, and the create request can explicitly set `confirm_duplicate: true` for a legitimate shared identity/contact combination. This is a warning gate, not a real-world identity guarantee. Create/update/archive append actor, patient, event and time to `patient_audit`; no patient text is copied to audit. Validation returns generic 422 for forbidden/invalid fields, 404 for missing IDs, and 400 for duplicate/archive conflicts. The list has a bounded page size of 100.
