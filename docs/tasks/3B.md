# Sprint 3 Task 3B — Arabic appointment UI

Date: 2026-10-24. Frontend only. Next task: **4A**.

The `/appointments` route shows a Cairo day view from the real appointment API, with a date selector, scheduled/cancelled/all filters, the API's total count and bounded page navigation. Rows show patient name from the administrative patient API, visit type, Cairo time and backend status. Loading, empty and retry states are explicit. The patient picker searches real active patients; no available-slot grid or invented counts are displayed. Booking and rescheduling require both start and end times because Task 3A's configurable duration policy has no read endpoint. The backend validates duration, working hours, past dates and overlaps. The UI translates Cairo wall times into unambiguous UTC instants, rejects skipped spring times and requests an offset choice during a repeated autumn hour. Cancel requires confirmation. Mutations disable their submit button while pending and invalidate appointment queries; a 409 retains the form, shows a clear Arabic message and refreshes the day view.

The existing FastAPI `require_role("doctor", "receptionist")`, session and CSRF checks remain authoritative. The UI sends only supported appointment fields and uses the in-memory CSRF token. It does not store credentials/tokens in localStorage or expose clinical data. No visit or billing features were added.
