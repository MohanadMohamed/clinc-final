# Sprint 5 Task 5B — billing frontend

Implemented an Arabic RTL billing page for both staff roles. It reads approved consultation/follow-up fees, lets staff create/issue invoices and record cash payments with confirmation, shows invoice balances and daily Cairo-date totals, and renders a printable administrative receipt. The overview page displays the same live daily API summary. Doctor-only fee editing is omitted for reception in the UI and remains blocked by FastAPI. The receipt and billing responses contain no clinical notes or diagnoses. No browser storage, CDN or cloud payment service is used.

The Task 5A API lacked invoice and payment listing, which the UI needs to review existing records and re-open receipts. Two read-only, staff-authorized endpoints were added: paginated `GET /api/billing/invoices` (optional patient filter) and `GET /api/billing/invoices/{id}/payments` (including reversal status). They use administrative billing schemas only; no migration or billing write rule changed. Mutation buttons disable while pending, use backend idempotency keys for invoice/payment retries, refresh affected TanStack queries, and show Arabic confirmation, error and success states.
