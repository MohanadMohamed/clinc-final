# Milestone 8A — packaging preparation checkpoint

Date: 2026-10-28. Dedicated branch: `codex/windows-8a-preparation`.

## Result

Windows preparation implemented; actual Windows build/GUI **NOT TESTED**. Linux and no `pwsh` runtime are available; no Windows host/VM was accessed. [Windows status and exact runbook](../WINDOWS_8A_STATUS.md) is the handoff. Next step: **8A-WIN-SMOKE**, not a new product sprint.

Existing client/LAN templates were preserved. Added a Windows-only onedir console PyInstaller spec and a script that builds current React assets, collects the client and stages doctor-only backend/assets. Reception receives only the client and an origin profile. No Vite, backend or PostgreSQL process is started by the client. A repeated build ID is refused. Build dependencies, including Pythonnet with declared Python 3.14 support, are pinned with release hashes; no packaging packages were installed on Ubuntu.

Launcher explicitly requests WebView2 on Windows; the spec excludes upstream MSHTML fallback (native missing-runtime rejection remains NOT TESTED). It sets private mode, no debug/file URLs/downloads/certificate bypass, validates origin-only TOML profiles, supports a GUI-free configuration check and sanitizes startup exceptions. URL parsing now rejects whitespace/backslashes to avoid ambiguous origins and sanitizes parser exceptions that could echo credentials in malformed URLs; a dedicated regression test covers the latter. Profile/renderer tests use mocks only; mock passes do not establish Windows acceptance.
