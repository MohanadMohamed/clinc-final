## Limits and safe operation

The HTTP proxy check verifies the HTML language/direction attributes and real endpoint transport; it does not execute React in a browser. Component tests execute React with test-only fetch fixtures. Together these are scaffold evidence, not browser or desktop acceptance. No clinical compliance/readiness claim is made.

The disposable script ignores configured database URLs, initializes its own private cluster, binds PostgreSQL only to a private Unix socket, and removes only its own temporary directory after stopping. It uses temporary local trust authentication without reusable credentials. Regular development uses generated passwords and separate migration/application roles as described in README. No `create_all()` or startup migration is used.

Loopback HTTP is development-only. The optional Compose database exposes loopback only and is never required for final runtime. Real clinic deployment still requires Windows-built packages, trusted HTTPS, services, secrets ACLs, offline runtime assets and backup/restore validation. Public health endpoints reveal generic status only. Production UI serving and desktop packaging remain later scope.
